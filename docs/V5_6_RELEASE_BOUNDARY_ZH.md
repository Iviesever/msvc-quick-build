## 相对 v5.5.0 的变更

- **分离构建与前台运行。** 普通和模块构建返回拥有自身数据的启动请求；构建侧对象离开作用域后，由独立前台运行器执行。构建失败不启动产物。原参数、工作目录、标准流、sanitizer 运行时策略及子程序退出码传递保留。环境初始化现在只把自己的输入重定向到 `nul`，为前台程序保留管道输入。作用域结束不证明外部写者停止。参见 [BuildCompletion](../cpp/src/app/targets/BuildCompletion.cpp) 和 [VisualStudioEnvironment](../cpp/src/msvc/toolchain/VisualStudioEnvironment.cpp)。
- **include 根目录拼写完全相同时避免重复转换。** [#194](https://github.com/Iviesever/msvc-quick-build/pull/194) 先比较原生路径；拼写不同仍走原身份比较。顺序、重复项、缓存校验及晚期 freshness 检查保留。这项结构优化不承诺每种负载都更快。
- **内部生命周期基础能力是增量、显式选择的。** 进程取消、调度准入／批次、物理写入域准入及已知写集合的只读清单用于后续工程。它们不启用 CLI 取消、可复用项目事务、自动恢复或常驻。参见 [进程生命周期](PROCESS_LIFETIME_ZH.md) 和 [写入域准入](WRITE_DOMAIN_ADMISSION.md)。M1b 与后续 v6.0 工作仍未完成。
- **修正证据记录及研究范围。** [#193](https://github.com/Iviesever/msvc-quick-build/pull/193) 将反复重写全部历史改为追加日志和兼容的最终 JSON；[#195](https://github.com/Iviesever/msvc-quick-build/pull/195) 将未获执行预算的编译器 PDB 研究与普通改动分离；[#188](https://github.com/Iviesever/msvc-quick-build/pull/188) 保留精确源码、实际被测程序和首错。这些是验证改进，不是新增公开 CLI 功能。

## 兼容性、安装与迁移

**现有 CLI 命令和 `mqb.json` 不需要因本候选新增迁移。** CLI 解析器、配置 schema 和 compile/link/archive 缓存文件实现，与比较用 v5.5.0 源码逐字节一致。这是限定范围的源码核对，不保证任意外部脚本或损坏缓存都兼容。既有有序选项、强类型 MSVC 准入、缺失输出修复及晚期 freshness 继续适用；不必仅因采用本候选而清空缓存。

`--run` 仍是前台运行，保留参数／标准流／退出码契约，不继承未来的构建取消策略。`plan` 和 `compdb` 不接入新的写入域预留 API。默认并行度不改为强制 `-j 1`。C++23、Windows/MSVC 仍是产品范围，不意味着新增平台或工具链认证。

公开编译参数边界未变：MQB 使用 `/Z7`，拒绝 `/Zi`、`/ZI`，保留 `/Fd` 的所有权，并从编译调用中移除环境 `CL` / `_CL_`。最终链接 PDB、外部 object/library/PCH/IFC 输入不全部受此边界覆盖。不能把它解释为所有 PDB 都安全，或静默更改研究夹具的参数。细节与保留失败见 [PROCESS_LIFETIME_ZH.md](PROCESS_LIFETIME_ZH.md)。

内部 C++ 调用者须审阅改变的进程、调度及准入契约；CLI 语法不变不代表二进制 ABI 兼容承诺。特别是，显式选择的受管进程策略不适用于有意保留后台后代的前台应用。写入域标记不授予接管遗留状态的权限。

使用 `Recorder` 的开发脚本须使用上下文管理器，或在正常和异常出口完成收尾。运行中读取 `calls.jsonl`；`calls.json` 在受控结束时生成。强制终止后留下的合法前缀不是完整实验，追加日志也不保证断电耐久性。参见 [DEVELOPMENT.md](DEVELOPMENT.md)。

正式包继续采用扁平、仅运行时的契约：`mqb.exe`、`VERSION`、`install.bat`、`install.ps1`、`uninstall.bat`、`uninstall.ps1`、`LICENSE`，并附 ZIP 校验文件。安装脚本未改。不得用标注 5.5.0 的 CI 包冒充官方 v5.5.0 发布包，也不得宣传为 v5.6.0。文档及这些限制保留在仓库／Release 正文，不放入运行包。参见 [安装](INSTALLATION.md) 和 [自举发布契约](SELF_HOSTING.md)。

## 停止与回退条件

遇到新的公开路径正确性／freshness／诊断退化、精确版本必需检查失败或异常跳过、缺失源码／程序身份、首批证据不完整，或新结果触发原适用性能门槛时，**停止发布**。不得提高阈值、删样本、补充耗尽的预算、重跑至绿、扣除猜测的观察器成本，或仅为通过验收而把未知失败归类为研究问题。

产品修复或回退必须有定位到受影响改动的证据，并通过单主题提交审阅。任何此类改动都会使旧产品冻结失效，需要新的影响范围验证计划；#188 已消耗的预算不能复用。没有合理改动依据时，保留已接受候选及已知风险，不虚构修复，也不静默撤销已接受的正确性工作。

部署回退时保留官方 v5.5.0 程序／安装包和项目配置。改变生成状态前，停止相关构建并确认其工具已经结束。比较版本时使用独立项目／输出副本或干净重建，不让不同版本并发共用可写输出。不得把删除未解决的写入域标记、PDB 或 IDB 当作安全恢复证明；降级程序不证明遗留写者停止。历史 tag 和资产不得覆盖。

## 剩余发布接手

完成本文档／风险审阅后，直接进入**独立 VERSION/release PR**，不再迁移记录器或重复冻结的 584 对。排除无关产品及研究变更。将 `VERSION` 改为 `5.6.0` 前，再读当前 main／CI，确认产品、构建与打包身份仍对应已接受候选。

该精确版本必须通过 Windows Debug 和 Release、seed／Stage 0/1/干净 2、包内嵌版本、七文件 ZIP／校验及安装器生命周期，并在原门槛下完成独立预登记的 ABBA，保留实际程序与首错。当前未改版本号候选的结果不能替代这些检查；本文不新增累计或研究测量预算。

合并 VERSION PR 会触发现有[发布契约](SELF_HOSTING.md)：Native Release 验证那个精确 main 提交，并使用已经验证的 Stage 1 包发布，不在发布时重新构建。最终生成的 Release 正文须通过正常发布流程包含本文的范围、兼容性与风险限定，不能假设自动生成的 PR 标题已经表达这些信息。未获授权或失败的发布门槛继续停止。本文档改动不创建 tag、Release 或新的二进制资产。
