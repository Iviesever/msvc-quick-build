# 只读构建产物空间盘点

**[English](STORAGE_INVENTORY.md) | 简体中文**

这是基于 v5.6.0 推进 #198 的第一个开发切片，不是已发布 v5.6.0 可执行文件中的功能，也不代表 v5.7.0 已完成。独立发布 PR 之前，VERSION 仍为 5.6.0。

## 命令与范围

```powershell
mqb storage
mqb storage --project C:\work\Rium --format json > C:\reports\rium-storage.json
mqb storage --help
```

默认项目就是当前目录；不会向上搜索 mqb.json、加载配置、发现工具链、构建、运行产物或创建 .mqb。指定的项目目录必须存在，其产物根目录复用 ProjectArtifactLayout。不存在的 .mqb 输出空盘点。未知或重复参数属于用法错误。本轮没有 clean、prune、执行删除开关、按年龄筛选或保留策略。

使用前停止构建器和其他写入者。只向标准输出和标准错误输出报告，重定向文件应放在 .mqb 外。读取句柄暂时拒绝写入与删除共享，因此竞争的写入或重命名操作也可能失败。这不是 build/clean 互斥协议、项目写租约，也不能保证外部不合作活动下的安全。

## 字节数与证据分类

JSON 的 schema_version 为 1，逐文件给出未四舍五入的无符号 logical_bytes、allocated_bytes、hard_links 和 physical_id；无法取得的字段为 null，不猜成零。GB 为 1,000,000,000 字节，GiB 为 1,073,741,824 字节。文本报告同样提供原始文件清单及汇总。

目录分组只包含直接子文件。扩展名、直接目录、证据分类各自构成已观察普通文件行的不重叠分组，已知逻辑字节总数可与 totals 闭合。按路径汇总的分配空间刻意重复计算硬链接路径；unique_file_allocated_bytes 按已观察的卷和文件身份去重，身份相同但大小冲突或出现任何盘点问题时留空。分配空间不等于可回收空间：根目录外的硬链接、文件系统去重、元数据及未观察的活动都未被这一数字证明。首轮压缩／稀疏文件的物理分配空间明确不可用；不包含备用数据流和目录元数据。

证据分类为 protected、unknown、cache_reference、shared_cache_reference。扩展名仅用于描述，不构成所有权证明。日志、生成输入、发布包、VS 状态、未知目录及非普通文件保持受保护。bin/obj/ifc/deps/scan/cache/pch 等常规位置也不会因此获准删除，它们的生命周期仍为 unknown。reclaimable_bytes、live_bytes、obsolete_bytes 始终为 null，deletion_authorized 始终为 false。

## 历史引用不等于所有权

只对已观察的 cache/link/*.linkcache、cache/archive/*.archivecache 且不超过 16 MiB 的文件复用现有 LinkCacheFile、ArchiveCacheFile 读取器，不保存或升级缓存。损坏、不支持、超限及解码错误明确报告。仅使用 MQB 既有 Windows 路径身份规则把绝对引用与已观察路径关联；不打开引用指向的外部路径，不猜测相对历史路径的基准。

每条记录输出缓存路径、目标输出、不透明签名及工具版本。多个缓存记录引用同一行，只能说明共享历史引用，不能证明当前共享所有权。各目标统计有交叉，不能相加。旧签名无法还原 Debug/Release 或完整配置，因此 by_configuration 归入 unknown。源码缺失、旧哈希或未被本次调用列出都不证明目标已经退役。未来删除之前，仍需另行建立可信的当前目标、共享依赖和显式 AOT 代际记录。

## 文件系统与错误边界

Windows 通过句柄读取 FileStandardInfo 和 FileIdInfo。观察某文件期间保留该文件及其祖先目录的句柄；拒绝穿过重解析点。固定句柄同时申请 FILE_READ_DATA（目录对应 FILE_LIST_DIRECTORY）和 FILE_READ_ATTRIBUTES，而不是仅申请属性访问，使只读共享掩码真正参与 Windows 共享检查。因此，即使只报告元数据，也需要读取文件数据／列出目录的权限。权限不足仍作为部分盘点报告，不回退到仅属性句柄。枚举限制为 1,000,000 行、128 层深度。这不是文件系统原子快照；即使遍历成功，atomic_snapshot 仍为 false。权限、占用、不支持的身份／分配信息、跳过的重解析子树及枚举／解码错误会留下 issues，尽可能输出部分报告并返回 1。致命初始化或输出错误可能只留下诊断而没有完整 JSON；调用方必须同时检查退出码、解析结果、complete 和 issues。

退出码 0 只表示有界遍历未记录错误，不证明目录不可变或允许安全删除。1 表示盘点／输出错误或覆盖不完整，2 表示参数／项目初始化错误。不删除文件、不终止进程或服务，也不改变编译参数、普通构建或缓存行为。

原始契约：[FILE_STANDARD_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_standard_info)、[GetFileInformationByHandleEx](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex)、[CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)。这些接口本身不证明可回收容量或并发写入安全。

## 复现与验收

新增 mqb_storage_e2e_tests.cpp，保留原来的 79 个原生测试程序，成为第 80 个。便携模型／报告测试覆盖字节闭合、引用去重、受保护项、未知／溢出值、JSON 转义和输出失败，不等于 Windows 测试。

Windows 文件夹具覆盖根目录不存在、有效／共享／损坏的旧缓存、真实硬链接、Unicode 与空格路径、已有写入者、观察时尝试重命名文件与祖先目录并申请写入／删除访问、句柄关闭后的成功访问／改名对照、文件名／内容／修改时间不变，以及真实 junction 拒绝。每项固定句柄测试都在断言前保存实际结果与原生错误码，失败结果也会保留。Debug、Release 各执行固定八次双源码构建：稳定目标首次／重复、源码改名、目标改名、配置切换、两个 AOT 命名目标及最后目标重复。最后运行一次生成程序，保留旧对象与旧目标，在不删除它们的情况下检查清单字节与文件数闭合。这些 AOT 名称仅是最小生命周期模型，不是 Rium 的实际 AOT 生成链。

storage-evidence 保存原始 argv、stdout、stderr、退出码及成功／失败盘点；CI 产物保留选定源码、目标输出和链接缓存，期限 30 天。现有 Windows Debug/Release、自举／打包、适用兼容检查和独立 19×4 ABBA 仍是验收门槛，不能用便携测试替代。不承诺固定空间节省比例。Rium 实测、可信所有权／配置状态、压缩／稀疏空间统计及安全 clean/prune 仍未完成。

## 成功调用关联记录（内部、显式启用）

下一生产者侧切片增加普通 EXE／DLL 目标的 `MsvcIncrementalTargetCoordinator::run_recorded`，以及最终链接的 `MsvcIncrementalLinkCoordinator::run_recorded`。它们仅执行一次原有已验证构建链，只在成功时返回拥有自身数据的结果与类型化关联。这是内部 C++ API，不是新 CLI、持久化登记表、目标事务或 storage JSON 变更。

目标记录按源码顺序保留源码／对象／依赖元数据／缓存引用、编译与实际传入链接阶段的选项（分别保留两者配置），以及可选的调用方目标／代际标注。未提供的标注保持缺失；修改标注不使缓存失效，也不把复用冒充新生成代际。共享对象分别出现在各目标记录中。additional／PCH 风格对象仍是输入引用，不冒充普通源码调度器拥有的输出。元数据／缓存路径是引用，不证明已经保存；编译警告及完整原始结果继续保留。

链接记录复用成功链接后实际封存的内存 LinkCacheEntry，或本次既有缓存校验接受的记录。不重新构造配方、不再次读取缓存、不新增文件系统查询或日志写入。executed 与 reused 分开；缓存保存失败保留原警告及 save_failed 状态，不声称记录已持久化。链接失败或缺失必需 MAP 输出时，返回原始错误，不返回成功记录。条件副产物来自既有链接器记录，不按扩展名猜测；这也不是 LINK 所有可能副作用或实际 argv 的完整清单。

这些是**成功调用的关联，不是物理输出观察或生命周期授权**。本轮不增加文件身份／内容哈希、并发写者排斥、当前内容核验、崩溃恢复、磁盘序列化或保留策略。旧缓存字节格式不变。历史成功仅作为调用方拥有的数据保存，之后的配置覆盖或失败构建可能改变实际文件。旧文件和 storage 的存活／可回收字段仍保持未知。静态目标与 PCH 支持见下节；模块接入、持久化与读回仍需另行推进，不能提前清理。默认 CLI 没有调用这一接口。

原有 80 个程序全部保留，新增独立 artifact-record E2E 程序，共 81 个。便携值模型测试检查可选标注和上游输入分离；八次确定性链接协调器调用覆盖执行／复用、同路径配置切换、原始链接失败、损坏缓存、缓存保存失败、条件 DLL 副产物及缺失 MAP。新增 artifact-record E2E 程序在每个原生配置下固定执行七次真实记录 API：首次构建、复用、共享目标、Release 覆盖、源码改名、预期编译失败、独立 DLL 目标；发现一次工具链、运行一次成功程序，保留 argv／输出／状态与完成摘要到 storage-evidence/records。这是在原八次 CLI 构建／五次盘点之外的新夹具，不重试失败的 EXE，也不代表 Rium 真实 AOT 验证。

## 静态库成功调用记录（内部、显式启用）

`MsvcIncrementalStaticTargetCoordinator::run_recorded` 和 `MsvcIncrementalArchiveCoordinator::run_recorded` 将同一生产者边界扩展到普通静态目标与最终 LIB。归档记录使用本次校验接受的实际 ArchiveCacheEntry，或 librarian 成功安装输出后封存的记录。记录最终 `.lib` 路径，不把 `.mqb-tmp` 临时路径当作完成产物。原始工具／安装／参数错误不返回成功记录；缓存保存警告仍为 save_failed，不宣称已经持久化。

架构、实际 LTCG 和透传参数直接取自既有 librarian 参数权威层；原始 `/LTCG` 参数在实际执行与缓存复用两种情况下都要正确记录。不增加第二套解析器、额外文件系统扫描或缓存重读。静态目标复用已有源码关联与调用方标签类型，分别保留编译配置及上游对象输入。只有显式记录调用才组装逐源码记录。默认 CLI 不启用；共享的默认实现有所改变，不能承诺零开销，仍须独立性能验收。

**归档配方身份不等于编译配置或文件内容身份。** Debug／Release 可能覆盖同一路径的对象和库，却保持同一个归档配方签名；必须另看编译选项及原始编译结果。调用方代际标签不保证唯一，缓存命中也不是新产生的库代际。PCH 创建者支持见下节；模块生产者、物理文件身份、并发写入边界、持久化／读回及 Rium 验证仍未完成。本轮不引入清理、事务／租约、保留策略或 storage JSON 变更。

原有 81 个程序逐字节保留。新增 static-record E2E 程序后共 82 个，每个原生配置固定十次使用模拟进程及真实缓存／文件 I/O 的归档调用：首次／复用、路由 LTCG／复用、缓存保存失败、损坏缓存、参数冲突、原始 LIB 非零退出、缺少临时输出及输出安装失败。六次真实静态记录 API 调用覆盖首次／复用、第二目标引用共享／上游对象、同路径 Release 覆盖、源码改名和预期编译失败。另用一次独立普通 EXE 消费者构建及运行验证最后成功的库，不修复重试失败的静态构建。夹具只发现一次工具链，使用单 worker。

原始 argv／stdout／stderr／状态、每次模拟与真实调用结果、每次原生成功的库及缓存副本保存在 `.mqb` 外的 `storage-evidence/static-records`，模拟和真实证据分开。这些仅是测试副本，不是产品持久化、全部生产者快照或并发证明。不重试替换失败。原有 storage 与 EXE／DLL 记录测试、完整原生 Debug／Release、自举／打包／安装以及未修改的独立 19×4 ABBA 仍各自保留为验收门槛。

## PCH 创建者成功调用记录（内部、显式启用）

`MsvcIncrementalPchCoordinator::run_recorded` 返回原始成功 PCH 结果与拥有自身数据的 `PchArtifactRecord`。记录复用同次调用既有的创建者请求投影：输入头文件、生成的创建者翻译单元、配对对象／PCH 输出声明、实际 create 绑定与编译选项、依赖／缓存引用、工作目录和可选调用方标注。不会把调用方原有的 use 绑定直接复制成创建者记录。头文件是输入，不是输出；生成的创建者源码与其编译输出分开表达。

executed／reused 取自实际编译结果，包括生成源码后既有的第二次新鲜度检查。saved／save_failed 取自原始类型化编译缓存保存警告，不解析文本或重读缓存；reused 不冒充本次保存。原有诊断和错误保持。warm 分支继续只读，同时间戳创建者修复及内部强制编译／重新校验机制不变。creator_source_materialization_required 只描述同次初始检查的需求，不证明独占或原子写入。源码生成失败、编译失败或缺失 PCH 不返回成功记录；旧记录不保证后续失败未改变实际文件。

**这不是 CompileCacheEntry 的导出。** 底层编译 API 没有暴露该记录；本切片不改底层协调器、不重读缓存、不重建签名，也不猜测 include／module 元数据。exact_cache_entry_captured、physical_identity_verified、complete_producer_inventory 和 deletion_authorized 均为 false。这只是创建者关联，不是 PDB 等副作用的完整清单、字节身份、持久化生命周期或删除授权。默认 CLI 不启用；共享包装仍可能有开销，须接受验证。storage JSON、缓存格式、持久化和并发行为不变。

原82个原生测试程序逐字节保留，新增 PCH-record 程序后共83个。每个原生配置固定十次确定性 PCH 调用（模拟 cl，真实协调器／缓存 I/O）：首次／复用、同 mtime 创建者修复、缺失 PCH 修复、缓存保存失败、编译器失败、工具成功但缺失 PCH、创建者源码被目录阻塞、缺失头文件及无效输出。完整执行为五次成功、五次预期错误、六个模拟进程。六次真实 PCH 记录调用覆盖首次／复用、同 mtime 修复、同路径 Release 覆盖、头文件变更及预期编译失败。一次普通 EXE 消费者构建／运行在故意失败**之前**使用最后成功的 PCH 与配对对象；不重试失败构建。只发现一次工具链，消费者使用单 worker。

原始命令、退出状态、警告及每次原生成功的创建者源码／对象／PCH／依赖／缓存副本保存在 storage-evidence/pch-records，并区分 mock／native。这些是 .mqb 外的测试副本，不是产品持久化或完整文件系统快照。旧 storage／EXE／静态库测试及既有原生、自举／打包／安装和独立19×4 ABBA门槛全部保留。标准 ABBA 仍缺少独立静态库／LIB 场景；此前明确接受的覆盖缺口与所有历史不利样本均未解决。扩大记录接入及最终5.7／Rium验收前仍需另行登记的静态库专项。模块生产者覆盖、实际文件身份和可靠读回仍是清理之前的独立前提。

## 模块编译批次成功调用记录（内部、显式选择）

`MsvcModuleCompileCoordinator::run_recorded` 只执行一次既有编译批次，整个批次成功后才返回原始结果和拥有自身数据的 `ModuleCompileWaveArtifactRecord`。提供者选择来自调用方传入、经既有计划检查接受的 `ModuleDependencyPlan`；每节点 `ModuleCompileArtifactRecord` 取自同次实际编译请求和成功返回。不增加检查、扫描、编译、提供者名称猜测或缓存重读。源码记录和头文件单元记录各自保持请求顺序，不依赖图层次或工作线程完成顺序。记录槽位在调度前分配，每个线程只写自己的槽位；默认路径不分配记录向量。

节点记录保存投影后的翻译单元、实际编译选项、缓存／依赖路径、可选的先前扫描引用、工作目录及传播的 `force_rebuild`。模块／头文件单元 IFC 输入是引用，与输出分开。命名模块接口声明对象和 IFC，普通消费者声明对象，头文件单元仅声明 IFC，遵循既有请求工厂。外部提供者仍是图／IFC 引用，不虚构成本批独占的新生产者。图不包含完整的 P1689 提供者声明；没有被引用的逻辑名称不靠猜测补齐。先前扫描路径不是本次编译的输出，也不证明扫描仍然有效。

executed/reused 和 saved/reused/save_failed 来自实际返回的编译结果及类型化缓存保存警告，原始结果保留全部警告和诊断。失败返回原来的批次错误，没有部分公开成功记录；此前成功的节点仍可能已经写入输出或缓存。这不是回滚、原子快照或当前状态证书。底层编译 API 不变，仍未导出本次接受／封存的缓存项；exact_cache_entry_captured、physical_identity_verified、complete_producer_inventory、deletion_authorized 保持 false。调用方标签只是标注，不是唯一代际。默认 CLI／模块目标调用方不启用记录；不增加持久化、物理身份、副作用清单、保留或清理授权。
