# 普通目标的同次编译缓存证据

[English](TARGET_WAVE_CACHE_EVIDENCE.md)

## 范围

普通 EXE/DLL 和静态库的显式 `run_recorded` 返回值，在原 result/record 之外，
拥有 `TargetCompileCacheEvidence`。其 compiles 按原 source 输入顺序存储逐源
`CompileCacheEvidence`；额外 object 输入不被冒充为本次本地编译产物。
原终端 link/archive 记录，以及物理身份、当前内容、完整清单和删除权限的 false
标志不提高。

共享 `TargetCompileWave` 只在显式记录路径捕获。默认 `run/inspect/CLI` 与独立
admission-stop 接口仍不记录。没有新增公共可复用执行票据、缓存补读、签名重建、
二次扫描、额外编译或另一套调度器。

## 捕获和私有拥有性

小目标和强制重建保持逐源调用一次既有下层 run_recorded。大目标仍一次检查所有
source，只执行紧凑的未命中列表。私有检查接线在热命中时直接移走真正接受的
缓存项；未命中时保留第一次检查时的工具链上下文。私有执行接线消费原请求、
原检查结果和该上下文，移动实际生成的缓存项及类型化保存失败。

调度前预分配独立 optional 槽位，各线程只写其原 source 下标，包括不连续的
未命中项。线程不向公共结果 vector 追加。所有工作结束后，拥有者按输入顺序
收集记录。返回值及其拷贝拥有请求、选项、工具链和缓存数据，不引用已经销毁的
工作槽位。它不是跨调用的执行授权。

## 重验证、保守重建和失败

共享文件证据屏障仍在未命中项执行完成之后。如共享快照失效，仍执行原有的
整目标强制重建。第二波开始时清空所有第一波捕获槽位；最终成功只能包含第二波
值，不能混入已经失效的热命中证据。执行和缓存封存阶段仍暂停共享快照；原 TLS
激活、恢复、调度停止策略不变。

源文件失败保持原输入顺序的错误选择；终端 link/archive 失败不发布部分成功
缓存记录。编译成功但缓存保存失败时，仍保留真实生成项、save_failed、原类型化
错误及警告。内部捕获缺失必须拒绝，不能合成空成功。失败不承诺回滚原操作已经
写出的文件；分配失败也不被包装成成功。

## 验证与证据边界

保留现有 **96** 个原生测试程序，不添加新测试可执行文件。在现有 target 测试
翻译单元中加入固定 **15** 次确定性 target 调用，覆盖直接冷热和强制路径、分离
检查、受控乱序完成、不连续未命中、执行后快照失效、缓存保存失败、源和终端错误、
历史拥有值以及 EXE/静态库两个拥有者。热命中必须逐源恰好一次成功载荷读取且零
保存；失效场景保留原来一次未命中加整目标强制波次的实际工作量。

实际计数先保存再断言。测试侧缓存副本在收集计数的作用域以外序列化，不计为产品
写入。已有真实 EXE/静态库 artifact-record 场景增加相同检查，但不增加 target
或编译调用。新候选仍必须完成自身 **Native**、**Release** 的真实 MSVC 执行、
全部原回归、自举和安装包验收；便携源码测试及使用明确 Win32 声明替身的 GNU/Linux
进程内 mock 执行，都不能替代 Windows、DLL 专项计时、真实系统副作用或 CI 验收。

历史严格检查通过完整文件指纹和精确逆变换继续检查原行为：当前文件与还原的旧
文件都必须匹配，新 helper 断言也受指纹保护；另一套新增测试直接检查实际新代码。
这不是对新旧断言或无关修改的宽松豁免。

## 成本和发布边界

显式捕获复制请求/工具链，分配逐源槽位，并使缓存载荷跨终端操作一直存活到返回值
释放。复制、分配、时间、峰值和驻留内存成本尚未量化。默认不启用不等于机器码
完全相同或零开销；功能验收之后仍须独立性能资格与集成审阅，不因便携测试通过而
批准默认或高频采用。

所有原性能失败、不利样本和已消耗诊断继续保留。本功能不授权持久化、writer 协议、
物理 producer 身份、安全 clean/prune、Rium 完整资格或 **v5.7.0** 发布；版本与
工作流保持不变。
