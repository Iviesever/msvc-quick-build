# 同次调用的精确编译缓存证据

[English](COMPILE_CACHE_EVIDENCE.md)

## 显式接口与来源

`MsvcIncrementalCompileCoordinator::run_recorded(request)` 返回
`RecordedIncrementalCompileResult`：原来的增量编译结果，以及拥有自身数据的
`CompileCacheEvidence`。它必须显式调用。既有 `run`、公开 `inspect`、目标批次和
CLI 调用方不请求记录。原 `IncrementalCompileResult` 和公开检查结构不新增缓存项，
检查结果仍不是可由调用方伪造或重放的执行票据。

复用分支直接移动原缓存校验器和有序 include 根检查最终接受的那个
`CompileCacheEntry`；执行分支在既有模块扫描证据封存和缓存保存尝试之后，移动
`executed->cache_entry`。不为记录额外加载缓存、重建签名、扫描、启动编译器或
事后读取 sourceDependencies。原封存逻辑本来需要的依赖读取保持，不删除也不重复。

记录拥有原请求和协调器用于检查的工具链上下文，包括有序环境值。环境可能敏感，
本接口不提供产品序列化器或环境转储。外部单独构造的执行器可能使用另一工具链：
`inspection_toolchain` 只描述协调器，`cache_entry.toolchain` 原样保留执行器实际
产生的值，不掩盖两者差异，也不认证外部工具链。

## 返回状态与限制

`CompileCacheEvidenceState` 区分 `reused`、`saved`、`save_failed`。复用不执行保存。
保存失败仍保留提供给原序列化器的精确缓存项和完整类型化 `CompileCacheFileError`，
原警告留在结果中；这不是持久成功。计划或编译失败转发原类型化嵌套错误，不返回成功
记录。若内部出现成功但无缓存项的不一致状态，返回 `cache_evidence_unavailable`，
不通过再次操作掩盖缺口。

记录为独立值，后续修改请求、覆盖磁盘、编译失败或修改另一份记录，都不能改写旧记录。
分配失败仍传播，这不是事务回滚；成功记录也不证明后来的失败未改变实际文件。

`exact_cache_entry_captured` 描述该接口的捕获行为，不是调用方自行构造结构体的
可信凭证。生产者身份、当前内容、完整生产清单和删除授权仍静态为 false。原缓存格式、
来源与输出顺序、重复元数据、可选扫描证据及错误警告保持。没有默认接入、物理身份
验证、跨调用代际存储、写者租约、保留策略、持久化层或 clean/prune 授权。

既有 PCH、模块和目标层产物记录仍走原来的路径，因此它们的
`exact_cache_entry_captured=false` 仍正确。新底层接口只是后续独立接线的前提，
不自动升级这些记录或已经合并的代际模型。

## 测试与保留证据

原生扩展放在既有 `incremental_loop_tests.cpp` 内；仍为96个原生测试程序和96个
生产编译单元。所有旧断言保留。严格历史适配器先验证整个扩展程序，再精确逆转已声明
追加并核对完整前驱 Git blob，不通配排除路径或替换旧指纹。原报告格式扩展保护保持。
便携测试还会逆转少量捕获接线，核对原协调器完整实现。

新增真实部分复用已经发现的工具链：固定13次记录调用，12次成功、1次故意编译失败；
9次编译器进程、1次真实命名模块扫描、0次链接。覆盖普通编译的冷构建、热复用、强制
重编译、损坏缓存、保存失败和编译失败；PCH 创建者冷／热路径；仅输出 IFC 的头文件
单元冷／热路径；命名模块冷／热路径及陈旧扫描拒绝封存。陈旧扫描案例显式控制源文件
时间戳，不是性能测量。新增部分按测试程序的 Debug／Release 构建选择配置；原测试
自己的固定配方不变。

独立确定性部分使用真实协调器和缓存 I/O，但编译进程明确为模拟：6次接口调用，其中
5次记录、1次默认，5次模拟进程。验证被接受的重复依赖、有序请求与环境的独立所有权、
热路径字节／时间戳不变、原嵌套错误、工具成功却缺输出，以及损坏依赖元数据。它不
执行真实编译器。上述数量均为新增部分，不包含原测试和工具链发现的既有工作。

必须使用全新 `storage-fixtures/compile-cache-evidence` 和
`storage-evidence/compile-cache-evidence` 目录。既有失败也上传规则保留原缓存编码器
序列化的成功记录、选定字段、故意损坏的输入、真实进程参数、原始输出、退出／错误及
首个失败前缀；不导出环境值。为相等性对照读取磁盘缓存属于独立测试依据，不是产品
接口生成记录的方法。测试副本不等于产品持久化或完整文件系统快照。缺完成标记不算
成功；测试不自动重试失败的真实案例或性能运行。

## 验收与后续

本变更不证明性能通过或零开销。编译期捕获选择避免默认路径无条件复制记录，但包装、
代码布局及显式调用分配成本仍须按既有规则评审。原 Performance819 失败和全部不利
样本不变，已消费的槽位诊断不重新分配。

合并决定前须验收本候选自己的 Windows Debug／Release 原生回归、原始附件、自举／
安装包和适用正确性结果，不能由便携源码检查替代。上层产物记录接入、持久化、受支持
真实写者协调、物理身份与安全回收仍为独立任务。VERSION 保持5.6.0，本变更不是
v5.7.0 正式发布。
