# 显式 clean：正向资格与拒绝契约

**[English](EXPLICIT_CLEAN_CONTRACT.md) | 简体中文**

## 1. 决定与准确边界

**决定：`CONTRACT_DEFINED`。初始受支持范围：`CURRENT_SESSION_EXE`。
当前实现：`EXECUTION_BLOCKED`。** 这两项声明彼此独立：
本文完成 PR255 的有限契约接手任务；它不新增 clean 命令，
不使任何既有文件获得删除资格，也不表示 #198 已完成。

已核对的 main 为 `c96c75750bcdebb1e8e31f69841d33ec4752e175`，tree 为
`d049d9fc95071796e5232f79655f6735e7322f89`。权威需求见
[#198 comment6091785630](https://github.com/Iviesever/msvc-quick-build/issues/198#issuecomment-6091785630)。
[决定／来源索引](EXPLICIT_CLEAN_CONTRACT.json)绑定准确来源身份、
独立审计、验收场景及缺失的权限依据。
下文的规范性要求描述未来行为；明确标为**当前**的事实描述本基线。
所提议的记录不是既有 C++ API。

第一条正向路径是：用户选定的一个普通可执行目标的当前主 EXE，
由同一受控写入方／清理方会话实际生成。
PDB、ILK、MAP、manifest、导入／导出文件、对象／PCH／IFC／HU 状态、
依赖数据及所有缓存均保留。它不选择旧 generation，
也不推断任何其他文件已经废弃。EXE-only 是最小正确性路径，
不代表 #198 所要求的以 PDB 为主的空间收益或完整 Rium 验收。

## 2. 备选方案与所选用途

| 备选方案 | 产品后果 | 决定 |
| --- | --- | --- |
| 同一受控会话内，由可追责生产者生成的当前 EXE | 提供具体成功路径，无需迁移磁盘上的所有权记录；要求真实写入完成与持续持有对象的交接 | 选择 `CURRENT_SESSION_EXE` |
| 之后的独立 CLI 按目标名称、扫描结果或已保存报告重新打开当前／legacy 文件 | 需要当前观察未提供的持久真实性、替换检测、恢复及参与方覆盖 | 本范围不准入 |
| 整个目标的历史 clean／prune，包括共享中间产物与符号文件 | 需要更广的生产者／使用关系、独立的符号／ILK 处理及历史保留策略 | 留待独立后续扩展 |

所选用户操作是显式丢弃目标的已知可重建当前 EXE。
受管理的调用方可在符合资格的构建后提供该操作，
在只读预览和显式执行选择之后进行，期间不启动 EXE。
构建目标本身绝不能请求清理。本文不引入 CLI 拼写或持久化计划格式。
从该会话导出的报告是描述性数据，不能重新导入为执行能力凭证。

## 3. 当前源码能够确立什么

| 当前机制 | 它提供的事实 | 它不提供的事实 |
| --- | --- | --- |
| `ProjectArtifactLayout::for_target` | 预期的 `.mqb/bin/<target>.exe` 与目标缓存路径 | 配置／架构身份：二者都不是此处的参数；另一配置可以覆盖同一路径 |
| 源码与 PCH 布局 | 按源码键分配的对象／依赖／IFC／缓存路径；PCH 的目标／配置／架构路径 | 所选目标的独占使用；源码中间产物可能共享 |
| Storage inventory／storage association | 有限的文件观察及其与所提供未验证声明的关联 | 当前生产者所有权、完整依赖使用、退役决定或删除权限 |
| 普通目标的 recorded 结果 | LINK 完成／缓存事实及逐源编译缓存证据，包括在已提供时捕获的准确条目 | 主 EXE 在完成后的物理／内容封存，或完整的实际终端配方 |
| 纯已知写入收集 | 类型化的可能写入、由实际拥有方选定的缓存路径及显式未解决副作用 | 实际执行的最终 argv、闭合的原生副作用集合或准入凭证 |
| `WindowsWriteDomain` | 持有的本地 NTFS 目录身份；合作式持久标记预留 | 生产调用方集成、递归排他、写入方完成／reset 或恢复 |
| `WindowsWriteInventory`／`observe_storage_file` | 清单保留私有的准确父目录固定句柄；单文件观察器只在调用期间持有叶子／祖先 | 带内容和执行权限、从生产者到清理方连续移交的叶子／完整祖先链能力凭证 |
| 根进程返回／前台作用域退出 | 该执行边界文档规定的结果 | 未跟踪子进程、共享服务、旧构建方或运行中产品的完成 |

不要抹去现已具备的能力：普通 `RecordedTargetResult`
包含 `TargetCompileCacheEvidence.compiles`，编译缓存证据可以携带
`exact_cache_entry_captured=true`。其余权限标志仍须分别看待。
另一方面，LINK 进程成功退出并不封存当前主 EXE。
已知 LINK 写入明确保留 ILK／LTCG／对象指令／原生副作用缺口。
条件副产物记录不构成删除这些文件的许可。

独立源码审计记录了：本基线中的 `collect_prewrite_inventory`、
`try_reserve` 和 `begin_writes` 均未被生产路径采用。
`begin_writes` 将 reserved 转为 writing；它不验证生产者，也不等待子进程。
不得通过删除标记、正常析构、PID 检查、经过时间或进程退出来绕过
刻意保留的 completion／reset 缺失边界。

## 4. 初始正向范围

以下条件必须同时满足。任何条件无法确立，都必须在发出删除请求前
返回具名拒绝或不可用结果。

1. 用户选择一个准确的普通 `TargetKind::executable` 目标及其
   已解析的配置、架构、MQB／工具链身份、源码集合、按顺序生效的选项、
   已解析输入和执行目录。目标必须使用受支持的普通路径；
   在本初始范围中，不包含 PCH／模块／HU、额外对象生产者、
   静态库／DLL 目标、任意输出覆盖或构建后运行。
2. 所选操作使用显式源码集合及已经选定的便携工具链。
   这避免隐式准入 discovery 和自动 VS／bootstrap 阶段；
   它不证明 cl／link 没有私有临时文件、指令、服务或环境副作用。
   这些剩余副作用需要第 7 节规定的写入方权限依据。
3. 该准确会话中的真实终端 LINK 操作已成功。
   负责此操作的拥有方在对象／库路由及后期新鲜度决定之后，
   记录最终有效调用，再在写入排他持续成立时绑定实际主 EXE。
   no-op／缓存命中、候选配方、调用方标签、仅有进程退出，
   或历史 recorded 结果，都不能签发第一份当前输出收据。
   no-op 构建可继续正常工作，只是不获得这项新的清理能力。
4. 结果是本地 NTFS 上、只有一个链接的普通叶子文件，
   位于经过验证的类型化输出边界内，并与所生成对象及内容匹配。
   它不存在重解析／ADS／命名空间歧义，也没有受保护／共享／运行时使用否决项。
5. 保留的请求仍能解析所需的源码／工具输入及一条受支持的重建路径。
   已知缺失或不可用的依赖不能被称为可重建。
   可重建表示受支持的目标能够再次构建；
   它不承诺未来字节完全相同，也不承诺工具永久可用。
   预览与执行之间的请求／输入绑定变化必须使计划失效，
   不能悄然改变所选构建。
6. 真实参与的写入方／启动器准入入口已经停止新准入，
   核清已准入工作，并向清理方移交仍有效、不可伪造的完成能力凭证。
   原生后端还须独立完成对持续持有对象的删除、
   以及运行中／已映射映像拒绝行为的资格验证。

**本范围的当前结果被第 10 节的 A1–A5 阻塞。**
其规定的成功转换是明确设计且可测试的；
在这些实现权限依据缺失时，不应交付永远拒绝的 CLI。

## 5. 由生产者拥有的当前输出收据

收据是拥有自身资源、不可复制且绑定到有效会话的能力凭证，
绝不是由任意调用方填充的结构或一组值为 true 的布尔标志。
它在概念上包含以下字段：

| 绑定 | 必需内容及负责的拥有方 |
| --- | --- |
| 目标请求 | 目标类型／名称、配置、架构、按顺序解析后的选项、输入／用途绑定及对其负责的解析方 |
| 实际执行 | MQB 与编译器／链接器／工具链身份、最终有效配方／argv、适用时的响应文件展开／绑定、有效环境／cwd，以及由其既有拥有方提供的终端成功证据 |
| 物理对象 | 持有的权限目录／祖先身份、准确的相对 EXE 叶子、持续持有的叶子身份，以及由 Windows 边界提供的内容绑定和受支持属性／链接数 |
| 生产者生命周期 | 准确的准入入口实例、写入 epoch、准入关闭及完成记录；所选边界内不存在影响它的未知未完成写入方 |
| 产品使用 | 所选输出不是另一目标保留的输入／工具、已发布／受保护资产或已启动／已映射产品；可追责的使用边界必须明确 |
| 同意与消费 | 准确的预览选择、不可变计划身份及一次性执行选择；移动／消费会使其他使用失效 |

有效配方证据归其生产者所有。不能把既有 LINK 缓存字段、签名
或 prewrite 候选重新标为实际终端命令。
当前源码没有捕获这里的全部字段。
源码配置发生变化或 EXE 在原位被替换时，
不能仅因目标名称、文件 ID、大小或 mtime 没变就让收据继续有效。
持续持有的固定句柄、内容绑定和写入 epoch 各自覆盖不同的失效情形，
三者均为必需。

原始环境值以及命令参数或 response 文件中的秘密只由其内存拥有方持有。
预览／导出报告只能包含允许公开的非敏感身份或经过脱敏的描述性摘要。
此类摘要不能重建收据，也不授予执行权限。

第一份收据仅限当前进程／会话及连续的对象生命周期。
新进程、释放固定句柄、拥有方放弃、epoch 改变或权限根目录被替换，
都会使它失效。本契约不引入普通 generation wire／archive、
加密签名方案、持久化事务或恢复声明。

## 6. 资格与强制排除项

| 分类 | 初始范围中的处理 |
| --- | --- |
| 所选当前 EXE 满足全部生产者、输入／用途、写入方及物理条件 | 仅获得进入附带检查条件的执行转换的资格 |
| 预期 EXE 路径没有当前生产者收据；legacy 或从外部复制的 EXE | 所有权未知；保留 |
| Debug／Release 或架构／选项请求与收据不同 | 请求过期或不匹配；即使路径相同也保留 |
| EXE 被另一目标用作工具／输入，或属于保留依赖、发布资产或活动产品 | 共享／受保护／使用中否决；无论目标类型如何均保留 |
| LINK PDB、compiler PDB、ILK、MAP、manifest、DLL／导入／导出文件 | 不在初始选定角色集合内；保留；须区分各类 PDB 与 ILK |
| 对象、PCH、IFC、HU、扫描／依赖状态及任何编译／链接／归档／discovery／工具链缓存 | 保留；不递归删除，也不删除同级文件 |
| 源码／配置／外部输入、生成输入、日志／失败样本、发布 ZIP／校验和／manifest、VS 状态、未知目录或 `.mqb/tmp` 内容 | 受保护或未知；保留 |
| 多个硬链接、未知链接数、目录／重解析叶子、重解析／已变化祖先、大小写／命名空间歧义或不支持的文件系统 | 物理拒绝；不删除别名链接，也不作尽力回退 |
| 在已证明不变的父目录下，准确叶子缺失 | 报告已经不存在；不删除、不计入任何已释放字节；不确定性／大小写冲突不等于不存在 |
| 依赖／用途覆盖未知、未核清的写入方／服务，或未确立运行中／已映射映像状态 | 权限依据不可用；保留 |

物理分类与当前内容不能确立所有权或独占使用。
反过来，有效的逻辑收据也不能豁免物理拒绝。
年龄、访问时间、扩展名、字节大小、是否在扫描结果中、
空缺口向量、过期标记或未出现在某次调用中，都不能覆盖这些规则。

## 7. 参与的写入方与运行中产品

新的准入入口必须是对既有拥有方的显式启用式组合，
不能成为另一套并行构建计划器。
任何已准入阶段在创建父目录、写缓存或提交原生工作之前，
都必须处于所声明的会话及物理权限边界内。
既有仅收集 API 可以提供声明；
未解决条目在实际拥有方完成资格验证前，仍然是未解决条目。

| 参与者 | 必须参与的边界或拒绝条件 |
| --- | --- |
| 普通编译和 LINK，以及其输出父目录／缓存拥有方 | 在第一个副作用前进入；保留后期新鲜度、路由和原始错误；完成必须覆盖已提交工作及全部已准入写入 |
| Discovery 与自动 VS／bootstrap | 从初始“显式源码／已选定工具链”范围中排除；调用它们的调用方在这些生产者加入前被拒绝 |
| PCH、模块／HU／provider、librarian、额外对象或外部输出生产者 | 排除；不得悄然把它们的输入视为拥有的输出 |
| 原生后代进程／私有或共享服务 | 使用已经证明能够覆盖实际生产者副作用的边界；仅根进程成功或根句柄关闭均不充分 |
| 受管理的前台启动、调试器或产品使用 | 在整个 clean 区间阻止启动；任何活动中或未知使用都拒绝 clean。初始路径不运行生成的 EXE |
| 能够到达该边界的旧 MQB、其他构建工具或不合作写入方 | 不声明兼容性。除非有单独证明的物理隔离／参与方边界将它们排除，否则拒绝；安装新二进制或添加清理方标记均不充分 |

当前可取消的 `WindowsProcessRunner` 只有在使用相应 token 时，
才提供更强的 job／成员完成边界。
当前普通编译器／LINK 及前台调用不会因此自动获得该边界。
即使 job 边界已完成资格验证，也不能覆盖任意 service／WMI／非后代写入方。
`/Z7`、便携工具链选择、空闲快照及仍存活的 mspdbsrv PID，
各自留下不同问题；没有哪一个是通用完成证书。

未来准入入口必须关闭准入、核清每项已准入操作，
并在没有失去排他保护的间隙时移交完成凭证及对象固定句柄。
下一写入 epoch 只能在清理方结束，
或在已证明的释放协议下明确放弃且未发生修改之后开启。
拥有方死亡、未完全排空或修改不确定，都会留下未解决状态。
本范围不导入、reset 或删除既有未解决标记。
不新增终止全局服务、按锁龄接管、自动恢复或整个项目的新事务。

## 8. 预览、执行与物理连续性

预览对构建文件是只读的：既不创建输出目录，
也不设置删除处置、不改变属性、不移除标记。
它报告准确的所选条目、分类、拒绝原因、
逻辑字节数及可用的分配空间观察；它不是磁盘空间回收估算。
有效调用方拥有计划和同意边界。

对于符合资格的执行转换，在预览至执行的整个区间，
持续保持写入方／启动器排他及经过验证的祖先／父目录／叶子句柄。
不得丢弃只读固定句柄，再以删除权限重开路径，并假定身份仍然有效。
原生设计必须取得兼容且具删除能力的句柄，
不能留下不受保护的权限升级间隙；
否则须拒绝，或在任何修改前以新的用户同意重新开始整个预览。
固定句柄失败时，不得回退到仅属性句柄，也不得跟随重解析点。

每次修改前，立即重新验证计划／准入入口／epoch、
请求／用途与内容绑定、准确的祖先／叶子身份、
类型、链接数、删除状态及受支持访问权限。
顺序由预览固定，绝不扩展到同级文件或目录树。
一旦验证失败，保留受影响文件并停止后续删除请求，
报告未尝试的条目。

Windows 后端必须在同一个持续持有的叶子句柄上请求删除处置，
不得回退到之后按路径调用 `remove`／`DeleteFile`。
运行中／已映射映像及不兼容访问必须保持在拒绝集合中。
本轮未选择高级 POSIX／替换标志、强制属性更改或绕过映射的方式。
任何尚未证明的原生行为都继续被 A5 阻塞，等待显式 Windows 资格验证；
这些文档决定不执行原生实验。

Microsoft API 契约仅支持此处使用的原语事实：
访问与共享兼容性、对持有句柄比较文件身份，
以及在具备适当权限时基于句柄设置删除处置。
它们不证明 MQB 所有权、写入方已经完成或空间立即回收。参见
[CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)、
[FILE_ID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info)、
[SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)
与 [FILE_DISPOSITION_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_disposition_info)。

## 9. 结果、中断与重建行为

区分 `not_attempted`、`refused`、`already_absent`、
`delete_requested`、`closed_name_absent`、`failed` 和 `outcome_unknown` 阶段。
记录实际原生错误、首个失败、路径及物理身份、所尝试动作、
删除处置／关闭／后置条件观察，以及每个后续未尝试条目。
仅删除处置调用成功，只能记为 `delete_requested`。
只有经过验证的关闭及同一父目录下的后置条件，
才能支持相应的名称不存在声明。
不确定的后置条件仍为未知；不得对重新打开的路径重试，
也不得把其计划大小计作已回收空间。

分别保留预览逻辑字节数、已观察的分配字节数、
已成功移除的名称，以及实际测得的卷空间变化。
不支持或未测量的分配／回收仍为 null／不可用。
硬链接别名记账不得重复计算同一物理文件。
本 EXE-only 范围拒绝多链接文件，
不作解除链接／回收空间的承诺。

在第一次修改之前，先取得保留操作记录的能力。
如果结果记录变得不可用，停止后续修改；
通过仍可用的渠道呈现已经知道的结果，并保留未解决操作。
不得删除原始日志来腾出空间。
进程中断／断电可能使最后一次已尝试操作的结果未知；
不声明跨文件原子删除、回滚、持久日志或自动恢复。
后续会话不能把旧计划当作权限依据继续执行。
它必须使用独立准入的恢复或新的生产者路径，
并保留旧的不完整证据。

当前 LINK 决策包含 `missing_output`。
保留缓存记录不会使缺失 EXE 成为缓存命中。
未来端到端资格验证必须证明所选目标能够重建，
且保留目标维持原有新鲜度判断／行为。
不得抹去缓存，也不得假装所有缓存命中都失效；
不得声称未来的 clean／rebuild 测试已经运行。
