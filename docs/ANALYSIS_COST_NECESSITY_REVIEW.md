## 3. Acceptance that exists before new data

Preparation identity, strict semantic admission and evidence integrity can be
specified before data. They answer different questions from whether a particular
product use is acceptably costly. [Typed semantics][semantics] constrain record
identity, order, units, mode separation and ownership relations; valid bytes do
not authenticate a producer or establish representative performance.

| Acceptance scope | Available now | Missing for a positive product-cost decision |
|---|---|---|
| Preparation | Exact frozen bytes and closed zero/null/false state | Execution authority |
| Fixed-substitute semantics | Frozen prepared/call identity, five ordered observations, strict values and final integrity rules | Real producer and representative cost evidence |
| Product use | Conservative explicit/nondefault restriction and current HOLD | Selected caller/trigger/frequency, supported inputs/platform, retained object lifetimes, accountable cost requirement and action for acceptable/adverse/invalid evidence |

The historical registration expressly had no numerical product budget. The
[performance governance rule][governance] does specify a separate external-no-op
HOLD gate: median paired candidate-minus-baseline delta **>1 ms AND** median
individual paired percentage change **>10%**, within the registered schema-v3
19-scenario/four-pair profile. This is an existing scoped criterion; it cannot
be transferred to pure codec nanoseconds, requested allocations, Linux HWM or
unlike operations. Not crossing it is not complete product approval.

A future criterion must follow the intended product decision and a defensible
requirement before new observations. It must name metric/unit, operation and
owned-result lifetime, supported workload/environment, rationale and decision
consequence. A nonnumeric rule is sufficient only if it actually decides that
cost question. If no requirement can be justified, record its absence; measuring
first does not create one.

## 7. One finite next handoff

Create **one #198 ordinary-generation consumer, operation and owned-result
lifetime decision** for whether and how selected historical claims/retention
are needed across invocation boundaries. This is a product design prerequisite
following the completed necessity review.

1. Name the intended caller or explicit library-use contract, trigger, consumed result, invocation
   frequency, input shape/platform and API or composition. If no consumer is
   selected from the existing #198 need, record `DEFER`.
2. Account for borrowed inputs and all owning live/archive/wire/decoded/model
   values: what coexists, who owns each value, when it is released, and what must
   cross the invocation boundary. Identify missing writer/persistence guarantees
   without assuming they already exist or authorizing their implementation.
3. State alternatives and the information that could change the choice. Locate
   the accountable cost requirement and its metric/window/decision consequence,
   or record the missing source. Use a narrow decision-owner clarification only
   if the records cannot resolve that concrete requirement.
4. End with a yes/no recommendation on whether a distinct measurement proposal
   deserves further static design. With no selected consumer or defensible
   requirement, record `DEFER`, retain HOLD/BLOCKED and stop that measurement
   path; do not repeat this necessity review or manufacture a threshold.

That handoff defines neither a study matrix nor a registration, implementation
or launch. Any later positive proposal must still satisfy all seven blockers.
