# Plan: bounded consumer and result-lifetime decision

## Scope and chosen approach

This is a static product design deliverable authorized by the prior handoff and
the user's continuation. It does not implement a product consumer. Preserve the
main/base `7dea446ea63c180e0af4a5ab5b499c244fbeaea6`, use an isolated worktree,
and submit a focused six-document change through GitHub Connector Git Data APIs.

The design compares three alternatives: current inventory behavior, a future
same-process explicit library consumer, and a future archive/byte consumer.
The result is `DEFER`: retain existing behavior, record the absent selected
consumer and accountable cost rule, and stop this measurement path. A supported
future contract would require materially new evidence and all seven prerequisites.

## Verification boundaries

No local project module, analyzer, runner, test, codec/compiler/MQB/MSVC/ETW or
fixed/real workload is needed or authorized by this static slice. The general
native build examples in contributor/skill instructions do not turn this
handoff into product execution. Source/Git/JSON/hash and archive-administration
checks establish the claims actually made. CI trigger source must be inspected
before creating the PR; actual results, not expected skip behavior, close CI.

The unchanged documentation check enumerates existing bilingual pairs. It does
not automatically cover a new pair; direct independent review is required.
Nothing in this plan lifts product-cost/PR250 HOLD, real-execution BLOCKED,
historical failed/invalid states, false authorities or the separate release gate.
