# PCH 同一次调用的缓存证据

[English](PCH_CACHE_EVIDENCE.md)

## 显式返回值，不是权限证明

`MsvcIncrementalPchCoordinator::run_recorded` 保留原 `result`、`record`，新增必须存在的拥有型
`cache_evidence`（`CompileCacheEvidence`）。独立的旧 `PchArtifactRecord` 仍只是投影，
`exact_cache_entry_captured=false` 不变；单独复制旧投影不会获得缓存项。附带证据仅描述本次
检查接受或执行封存的值，不证明生产者身份、当前文件内容、完整清单、持久性或删除权限。
四项权限标志继续为 false。

## 贯通原有检查路径

热命中由仅供 PCH 使用的私有接线保留原编译检查实际接受的值，包含有序 include 根检查。
随后仍走原来的只读结果路径，不再调用一次 `run_recorded` 来补缓存。不存在公开、跨调用或
持久化的可重放执行票据。

冷构建与修复保留初始检查、目录与 creator 写入、原有写入后编译重检，仅把这一次下层 `run`
替换为记录版本。附带的是最终重检接受或执行封存的值，不是修复前的缓存。相同时间戳的 creator
修复仍强制最终重检；证据保留实际的 force 请求，PCH 原结果继续保留 `source_changed` 语义和警告。
失败转发原 PCH/编译类型化错误，不发布成功记录。编译成功但缓存保存失败时，保留尝试保存的值及
准确类型化保存错误。不为记录增加缓存读取、签名重建、扫描或编译。

## 默认路径与成本

默认 `run` 使用 `run_impl<false>`；公开 `inspect`、CLI 和上层目标调用不启用新记录。显式路径
复制实际请求及检查工具链，并持有缓存项；环境按原顺序、重复项保存在内存，不序列化敏感值。
部分失败路径也支付复制和分配成本，不宣称零开销或有界内存。编译期排除不等于机器码或运行性能
不变；本候选仍需独立默认路径性能资格和集成决定，不自动继承 #241/#232 的风险接受。
本实现不登记新的性能执行。

## 回归范围

原 PCH E2E 仍为十次 mock 支撑的 API 调用（五成功、五预期错误、六模拟进程）、六次真实 PCH API
调用（五成功、一预期编译失败），以及原有 consumer 构建和运行。保留全部旧断言、错误日志和旧投影
输出。新增检查针对同一返回值验证双输出、实际选项、force、准确保存错误、阻塞字节和跨后续失败的
历史值保全。测试在 API 返回后使用原缓存编解码器保存独立证据，不是产品额外持久化。
热命中要求恰好一次成功缓存载荷打开、零缓存写入；其他原路径有固定上限。该计数不包含失败打开，
源码契约另外保护检查和重检调用点；启用计数不作为性能测量。

旧全量程序保护先精确逆转本扩展，并同时核对新旧完整文件指纹，不排除整个测试文件。便携源码/
合成检查及 Linux 语法检查不能替代 Windows Debug/Release。原生 CI 沿用原上传路径保留成功与失败
证据。本次不改工作流、96 程序登记、产品 TU 数、版本、持久化、写者协议、安全清理或 Rium 资格。
