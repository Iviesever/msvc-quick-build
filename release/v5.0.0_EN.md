# v5.0.0 — Native C++ Stable Release

**[简体中文](v5.0.0.md) | English**

MQB `v5.0.0` was released on **2026-08-12**. It is the first stable release from the native C++ mainline and the first stable version after the clean break from the former PowerShell implementation.

The release standardizes on three entry points:

- executable: `mqb.exe`
- command: `mqb`
- project configuration: `mqb.json`

## Highlights

### Native build pipeline

MQB now drives MSVC through its native C++ implementation:

- supports `.c`, `.cpp`, `.cc`, and `.cxx`;
- discovers Visual Studio or portable MSVC toolchains;
- supports smart source discovery for a single entry and exact source sets for multiple entries;
- keeps independent incremental compile, link, and archive caches under the project `.mqb/` directory;
- supports bounded parallel scan/compile with `-j` / `--jobs`.

### Targets and build policy

`v5.0.0` supports:

- `exe`, `dll`, and ordinary `static` targets;
- `MD` / `MDd` / `MT` / `MTd` runtimes;
- LTCG;
- `console` / `windows` subsystems;
- include paths, defines, library paths, libraries, and raw compiler/linker argv elements.

These policies can be set through the CLI or strict `mqb.json` configuration. Scalar options follow `CLI > mqb.json > default` precedence.

### C++ Modules / Header Units

The first stable release supports **project-local named modules** and **project-local header units**. Dependency topology is derived from MSVC `/scanDependencies` P1689 data rather than guessed from source text.

### Run after build

Executable targets can be run directly:

```powershell
mqb main.cpp --run -- input.txt "hello world"
```

Arguments after `--` are passed to the target program as structured argv.

## Upgrading from the PowerShell line

`v5.0.0` is an explicit compatibility boundary. The following legacy entry points are no longer shipped or automatically supported:

- `build.ps1` and the `build` compatibility command;
- `build-legacy.ps1` / legacy rollback;
- PowerShell profile injection;
- automatic migration of old installations;
- `msvc_list.json`;
- PowerShell-era single-dash aliases such as `-config`, `-std`, `-type`, `-run`, `-env`, `-flags`, and `-link_flags`.

Use `mqb --help` and `mqb.json` as the authoritative interfaces. Legacy spellings fail explicitly rather than silently entering a compatibility path.

## Installation

Download both release artifacts:

```text
msvc-quick-build-v5.0.0-windows-x64.zip
msvc-quick-build-v5.0.0-windows-x64.zip.sha256
```

Verify the checksum, extract the ZIP, then run:

```powershell
.\install.bat
```

The default install directory is:

```text
%USERPROFILE%\bin
```

Open a new terminal and verify the installation with:

```powershell
mqb --help
```

The first line should be:

```text
MQB 5.0.0 - MSVC Quick Build (C++ refactor)
```

The installer does not modify PowerShell profiles or create the legacy `build` command. `mqb.exe` uses the static MSVC runtime, so running MQB itself does not require a separate Visual C++ Redistributable installation.

Uninstall with:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$HOME\bin\uninstall-mqb.ps1"
```

## Known v5.0.0 boundaries

The following capabilities were **not part of the original v5.0.0 release**:

- external / prebuilt named-module IFC providers;
- MSVC toolchain-owned `import std;` / `import std.compat;`;
- static-library targets that require the Modules/Header Units pipeline.

These scenarios fail closed in this release. Capabilities added later on `main` must not be retroactively described as v5.0.0 features.

## Release validation

The official `v5.0.0` artifacts were produced and validated through MQB's self-hosting chain:

```text
pinned v5.0.0-rc.2 seed
        ↓
Stage 0
        ↓  MQB-built Release test graph
Stage 1
        ↓  clean build state
Stage 2
```

Release gates verified:

- pinned-seed checksum and executable identity;
- the complete **67/67 Release test** set at the time of release;
- Stage 0 → Stage 1 → clean Stage 2 self-host closure;
- packaged `mqb.exe` byte identity with the validated Stage 1 executable;
- exact package manifest and checksum;
- install / reinstall / uninstall lifecycle;
- tag agreement with `release/VERSION`, with publication consuming the already-validated artifact instead of rebuilding it.

The SHA-256 of the official Windows x64 ZIP is:

```text
eec1d8ae80ff8ade23f438ad53ec253ad67b36a81481759dc6bba0d108cc3d12
```
