# v5.0.0-rc.2 — C++ Refactor Release Candidate

This prerelease advances the standalone Windows x64 C++ rewrite after `v5.0.0-rc.1`. It is built and tested on the Visual Studio 2026 GitHub runner and keeps the PowerShell implementation as the legacy/default installation path while stable-v5 parity work continues.

## What changed since rc.1

- native C (`.c`) translation units are now supported alongside C++ sources
- C discovery is language-isolated: legal C identifiers such as `module`, `import`, and `export` do not enter the C++ module pipeline
- typed MSVC runtime selection through `--runtime MD|MDd|MT|MTd` and legacy-compatible `-runtime`
- typed executable subsystem selection through `--subsystem console|windows` and legacy-compatible `-subsystem`
- strict `mqb.json` v1 now supports `build.runtime` and `build.subsystem`
- runtime changes participate in compile identity and force the required downstream link; subsystem-only changes invalidate link identity without recompiling fresh translation units
- the runtime policy remains backend-owned, so a conflicting raw compiler argument cannot override the typed runtime choice

## Existing C++ RC capabilities

- standalone native `mqb.exe` with no PowerShell runtime dependency on the new CLI path
- Visual Studio / portable MSVC discovery
- single-entry smart source discovery and explicit multi-source targets
- incremental compile/link caches under `.mqb/`
- bounded parallel scanning/compilation via `--jobs`
- strict project configuration through `mqb.json`
- project-local named modules, including provider discovery and partitions
- project-local header units with P1689 topology, generated IFCs, freshness/rebuild propagation, and missing-IFC repair
- structured `--run` arguments and library/include/define/raw build-policy options
- real installed-MSVC cold/warm/mutation/repair coverage in the test suite

## Install this RC

1. Download `vscode-msvc-quick-build-v5.0.0-rc.2-windows-x64.zip` and its `.sha256` file from this prerelease.
2. Verify the SHA-256 checksum, extract the archive, and place its directory on `PATH`.
3. Run `mqb --help`; the first line must report `MQB 5.0.0-rc.2 - MSVC Quick Build (C++ refactor)`.
4. Try `mqb main.cpp --run` or `mqb main.c --run` in a project directory.

The packaged executable uses the static MSVC runtime, so the RC does not require a separate Visual C++ Redistributable installation.

## RC boundary

This remains a **release candidate**, not the final PowerShell-to-C++ cutover. The repository's existing `build.ps1`, `install.bat`, and PowerShell profile remain the legacy/default installation path.

DLL and static-library target kinds are not part of rc.2. Work on DLL target routing continues separately, and static libraries require a dedicated `lib.exe`/librarian pipeline rather than pretending they are linker targets.

External/prebuilt named-module providers and `import std` also remain intentionally unsupported/fail-closed. Stable v5 still requires the explicit parity campaign, installer/default-command cutover, and stable release engineering gates tracked in issue #26.

Please report a minimal reproducer when this RC differs from the legacy PowerShell behavior in a workflow that the native C++ CLI is intended to support.
