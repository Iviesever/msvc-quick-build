# v5.0.0 — Native Stable Release

`v5.0.0` is the first stable MQB release built from the native C++ mainline.

This release is a clean break from the former PowerShell implementation. Stable v5 has one supported executable, command, and project configuration format:

- executable: `mqb.exe`
- installed command: `mqb`
- project configuration: `mqb.json`

## Highlights

- native C and C++ translation-unit builds through MSVC
- Visual Studio and portable MSVC toolchain discovery
- single-entry smart source discovery and explicit multi-source targets
- incremental compile, link, and archive caches under `.mqb/`
- bounded parallel scan/compile execution with `--jobs`
- strict `mqb.json` project configuration and CLI-over-config precedence
- executable, DLL, and ordinary static-library target kinds
- typed MSVC runtime, LTCG, and subsystem policies
- project-local named modules and project-local header units with P1689-based topology
- structured `--run -- arg1 "arg 2"` program arguments
- native install, reinstall, and uninstall lifecycle
- stable-release self-hosting: the `mqb.exe` in the ZIP is built by MQB itself, not by CMake

## Self-hosted stable artifact

Stable publication requires a two-generation self-host closure.

The CI test/bootstrap binary (Stage 0) first runs the full Release test graph. Stage 0 then invokes MQB with the checked-in `cpp/mqb.json` project description to build Stage 1 without reading or invoking `CMakeLists.txt`. Stage 1 is copied aside, all `cpp/.mqb` state is deleted, and Stage 1 must rebuild MQB again as Stage 2 from a clean state.

Both self-hosted generations must report `MQB 5.0.0`. The stable ZIP packages **Stage 1**, not the Stage 0 bootstrap executable. Before upload, the ZIP's `mqb.exe` is required to be byte-identical to the validated Stage 1 binary.

The complete contract and manual self-build command are documented in `SELF_HOSTING.md` inside the release package and in `docs/SELF_HOSTING.md` in the repository.

## Breaking changes from the PowerShell line

Stable v5 does not ship or support:

- `build.ps1`
- a `build` compatibility command or PowerShell profile function
- `build-legacy.ps1` or legacy rollback
- automatic migration of an old PowerShell installation
- `msvc_list.json`
- PowerShell-era single-dash aliases such as `-config`, `-std`, `-type`, `-run`, `-env`, `-flags`, and `-link_flags`

Use the native CLI shown by `mqb --help`. Unsupported legacy spellings fail instead of entering a compatibility path.

## Install

1. Download `vscode-msvc-quick-build-v5.0.0-windows-x64.zip` and its `.sha256` file from the GitHub release.
2. Verify the SHA-256 checksum.
3. Extract the ZIP.
4. Run `install.bat` from the extracted directory.
5. Open a new terminal and run `mqb --help`.

The first help line must be:

```text
MQB 5.0.0 - MSVC Quick Build (C++ refactor)
```

The installer defaults to `%USERPROFILE%\bin`, records only installer-owned native state, does not modify PowerShell profiles, and does not create compatibility commands.

Uninstall with:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$HOME\bin\uninstall-mqb.ps1"
```

## Package integrity

The release workflow runs the full Release installed-MSVC test suite on the bootstrap build, verifies the embedded version, proves the two-stage MQB self-host closure, packages the Stage 1 self-hosted binary, creates the ZIP and SHA-256 file, extracts that exact ZIP, verifies its manifest and checksum, and runs the native install/reinstall/uninstall regression against the extracted package before upload.

For tag publication, the workflow requires the pushed tag to exactly match `release/VERSION` and publishes the already-validated workflow artifact without rebuilding it.

The packaged `mqb.exe` uses the static MSVC runtime, so a separate Visual C++ Redistributable installation is not required for the MQB executable itself.

## Unsupported module boundary

External or prebuilt named-module providers and `import std;` remain intentionally unsupported and fail closed. Those policies continue to be tracked independently from the stable-v5 release line.

## Historical prereleases

`v5.0.0-rc.1` and `v5.0.0-rc.2` remain historical prereleases. They are not rewritten to match the final native-only contract.
