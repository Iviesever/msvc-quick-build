# v5.0.0 — 原生稳定版 / Native Stable Release

**语言：简体中文（默认） | English below**

## 简体中文

`v5.0.0` 是 MQB 原生 C++ 主线的首个正式稳定版，也是与旧 PowerShell 实现彻底切割后的第一个稳定版本。

稳定版只支持一套实现、命令与项目配置：

- 可执行文件：`mqb.exe`
- 安装后的命令：`mqb`
- 项目配置：`mqb.json`

### 主要能力

- 使用 MSVC 原生构建 C / C++ translation units
- Visual Studio 与 portable MSVC 工具链发现
- 单入口 smart discovery 与多文件精确 source set
- `.mqb/` 下的增量编译、链接与归档缓存
- `--jobs` 有界并行 scan / compile
- 严格 `mqb.json` 配置与 CLI-over-config precedence
- `exe` / `dll` / 普通 `static` target kinds
- typed MSVC runtime、LTCG 与 subsystem policy
- project-local named modules 与 project-local header units，使用 P1689 拓扑
- `--run -- arg1 "arg 2"` 结构化程序参数
- 原生 install / reinstall / uninstall 生命周期
- 稳定版自举：ZIP 中的 `mqb.exe` 由 MQB 自身构建，而不是由 CMake 直接产出

### 自举稳定产物

稳定发布要求完成两代自举闭包。

CI 的 Stage 0 仅用于 bootstrap 与完整 Release 测试。Stage 0 随后使用仓库中的 `cpp/mqb.json` 调用 MQB 自身构建 Stage 1，全程不读取或调用 `CMakeLists.txt`。Stage 1 会被独立保存，随后删除全部 `cpp/.mqb` 状态，再由 Stage 1 从干净状态构建 Stage 2。

Stage 1 与 Stage 2 都必须报告 `MQB 5.0.0`。最终稳定 ZIP **只打包 Stage 1**，不打包 Stage 0。上传前还会验证 ZIP 内的 `mqb.exe` 与已验证的 Stage 1 二进制字节完全一致。

完整自举契约见发布包内的 `SELF_HOSTING.md`，以及仓库中的 `docs/SELF_HOSTING.md`。

### 与旧 PowerShell 版本的破坏性变化

Stable v5 不再发布或支持：

- `build.ps1`
- `build` 兼容命令或 PowerShell profile function
- `build-legacy.ps1` 或 legacy rollback
- 旧 PowerShell 安装的自动迁移
- `msvc_list.json`
- `-config`、`-std`、`-type`、`-run`、`-env`、`-flags`、`-link_flags` 等 PowerShell-era 单横线别名

请使用 `mqb --help` 展示的原生 CLI。不受支持的旧拼写会直接失败，不会进入兼容执行路径。

### 安装

1. 从 GitHub Release 下载 `msvc-quick-build-v5.0.0-windows-x64.zip` 与对应的 `.sha256` 文件。
2. 校验 SHA-256。
3. 解压 ZIP。
4. 在解压目录运行 `install.bat`。
5. 打开新的终端并运行 `mqb --help`。

首行应为：

```text
MQB 5.0.0 - MSVC Quick Build (C++ refactor)
```

安装器默认安装到 `%USERPROFILE%\bin`，只记录 installer-owned 的原生状态，不修改 PowerShell profile，也不创建兼容命令。

卸载：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$HOME\bin\uninstall-mqb.ps1"
```

### 发布完整性

发布 workflow 会先在 Stage 0 上执行完整 Release installed-MSVC 测试与版本验证，再证明两代 MQB 自举闭包，打包 Stage 1，自行生成 ZIP 与 SHA-256，重新解压该 ZIP，验证 manifest、checksum 与 Stage 1 byte identity，并直接针对解压后的发布包执行 install / reinstall / uninstall 回归。

Tag 发布要求推送的 tag 与 `release/VERSION` 完全一致；publication job 只发布同一 workflow run 已经验证过的 artifact，不会二次 rebuild。

发布包中的 `mqb.exe` 使用静态 MSVC runtime，因此 MQB 本身不要求额外安装 Visual C++ Redistributable。

### 当前模块边界

External / prebuilt named-module providers 与 `import std;` 仍明确不支持并 fail closed。这些能力独立于 stable-v5 发布主线继续跟踪。

### 历史预发布

`v5.0.0-rc.1` 与 `v5.0.0-rc.2` 保留为历史 prerelease，不会重写以匹配最终 native-only 稳定版契约。

## English

`v5.0.0` is the first stable MQB release from the native C++ mainline and the first stable release after the clean break from the former PowerShell implementation.

Stable v5 has one supported executable, command, and project configuration format:

- executable: `mqb.exe`
- installed command: `mqb`
- project configuration: `mqb.json`

### Highlights

- native C and C++ translation-unit builds through MSVC
- Visual Studio and portable MSVC toolchain discovery
- single-entry smart source discovery and explicit multi-source targets
- incremental compile, link, and archive caches under `.mqb/`
- bounded parallel scan/compile execution with `--jobs`
- strict `mqb.json` project configuration and CLI-over-config precedence
- executable, DLL, and ordinary static-library target kinds
- typed MSVC runtime, LTCG, and subsystem policies
- project-local named modules and project-local header units with P1689-based topology
- structured `--run -- arg1 "arg 2"` program arguments
- native install, reinstall, and uninstall lifecycle
- stable self-hosting: the `mqb.exe` in the ZIP is built by MQB itself, not directly by CMake

### Self-hosted stable artifact

Stable publication requires a two-generation self-host closure.

The CI Stage 0 binary is used only for bootstrap and the full Release test graph. Stage 0 then invokes MQB with the checked-in `cpp/mqb.json` project description to build Stage 1 without reading or invoking `CMakeLists.txt`. Stage 1 is copied aside, all `cpp/.mqb` state is deleted, and Stage 1 must rebuild MQB again as Stage 2 from a clean state.

Both Stage 1 and Stage 2 must report `MQB 5.0.0`. The stable ZIP packages **Stage 1 only**, never Stage 0. Before upload, the ZIP's `mqb.exe` must also be byte-identical to the validated Stage 1 binary.

The complete contract is documented in `SELF_HOSTING.md` inside the release package and in `docs/SELF_HOSTING.md` in the repository.

### Breaking changes from the PowerShell line

Stable v5 does not ship or support:

- `build.ps1`
- a `build` compatibility command or PowerShell profile function
- `build-legacy.ps1` or legacy rollback
- automatic migration of an old PowerShell installation
- `msvc_list.json`
- PowerShell-era single-dash aliases such as `-config`, `-std`, `-type`, `-run`, `-env`, `-flags`, and `-link_flags`

Use the native CLI shown by `mqb --help`. Unsupported legacy spellings fail instead of entering a compatibility path.

### Install

1. Download `msvc-quick-build-v5.0.0-windows-x64.zip` and its `.sha256` file from the GitHub Release.
2. Verify the SHA-256 checksum.
3. Extract the ZIP.
4. Run `install.bat` from the extracted directory.
5. Open a new terminal and run `mqb --help`.

The first help line must be:

```text
MQB 5.0.0 - MSVC Quick Build (C++ refactor)
```

The installer defaults to `%USERPROFILE%\bin`, records only installer-owned native state, does not modify PowerShell profiles, and does not create compatibility commands.

Uninstall with:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$HOME\bin\uninstall-mqb.ps1"
```

### Package integrity

The release workflow runs the full Release installed-MSVC test suite on Stage 0, verifies the embedded version, proves the two-generation self-host closure, packages Stage 1, creates the ZIP and SHA-256 file, extracts that exact ZIP, verifies its manifest, checksum, and Stage 1 byte identity, and runs the native install/reinstall/uninstall regression against the extracted package before upload.

For tag publication, the workflow requires the pushed tag to exactly match `release/VERSION` and publishes the already-validated workflow artifact without rebuilding it.

The packaged `mqb.exe` uses the static MSVC runtime, so the MQB executable itself does not require a separate Visual C++ Redistributable installation.

### Unsupported module boundary

External or prebuilt named-module providers and `import std;` remain intentionally unsupported and fail closed. Those policies continue to be tracked independently from the stable-v5 release line.

### Historical prereleases

`v5.0.0-rc.1` and `v5.0.0-rc.2` remain historical prereleases and are not rewritten to match the final native-only contract.
