# v5.0.0 — 原生稳定版 / Native Stable Release

**语言：简体中文（默认） | English below**

## 简体中文

`v5.0.0` 是 MQB 原生 C++ 主线的首个正式稳定版，也是与旧 PowerShell 实现彻底切割后的第一个稳定版本。

稳定版只支持：

- 可执行文件：`mqb.exe`
- 安装命令：`mqb`
- 项目配置：`mqb.json`

### 主要能力

- MSVC 原生 C / C++ translation-unit 构建
- Visual Studio 与 portable MSVC 工具链发现
- single-entry smart discovery 与 exact multi-source sets
- `.mqb/` 增量 compile / link / archive cache
- `--jobs` 有界并行 scan / compile
- strict `mqb.json` 与 CLI-over-config precedence
- `exe` / `dll` / ordinary `static` targets
- typed MSVC runtime、LTCG、subsystem policy
- project-local named modules 与 header units，使用 P1689 拓扑
- `--run -- ...` 结构化程序 argv
- native install / reinstall / uninstall lifecycle
- **MQB 自己承担 MQB 的开发、测试与稳定版构建**

### 全程 MQB 构建

Stable v5 的开发/测试/发布链不使用 CMake 或 CTest 生成或执行 MQB 测试图。

首个 stable 发布需要解决 bootstrap 问题，因此 CI 使用历史 `v5.0.0-rc.2` 的 MQB 作为**固定 seed**。workflow 强制校验该历史 release ZIP 的 SHA-256 与 `mqb.exe` 身份；seed 只构建当前源码的 Stage 0，不会进入稳定包。

```text
固定历史 seed MQB（SHA-256 verified）
        ↓  MQB 构建当前 42-TU 源码
Stage 0（当前源码 / Release test generation）
        ↓  Stage 0 用 MQB 构建并运行 67/67 Release tests
Stage 0 → Stage 1（MQB 构建 MQB）
        ↓  删除 cpp/.mqb
Stage 1 → Stage 2（MQB 再次构建 MQB）
```

Stage 0、Stage 1、Stage 2 都必须报告 `MQB 5.0.0`。最终稳定 ZIP **只打包 Stage 1**。上传前还会验证 ZIP 中 `mqb.exe` 与已验证 Stage 1 byte-identical。

完整契约见发布包中的 `SELF_HOSTING.md` 与仓库 `docs/SELF_HOSTING.md`。

### 67-test native gate

`tests/native/run_native_tests.ps1` 是权威测试 driver：

- 从 `cpp/mqb.json` 使用 production source manifest；
- 强制要求恰好 67 个 `*_tests.cpp`；
- 使用当前 MQB 构建每一个 test executable；
- 对 CLI E2E 测试传入当前 MQB 自身；
- 直接运行并要求 67/67 success。

因此 stable release 的 Release tests 与日常 Debug tests 使用相同的 MQB-native 测试模型。

### 与旧 PowerShell 版本的破坏性变化

Stable v5 不再发布或支持：

- `build.ps1`
- `build` 兼容命令或 PowerShell profile function
- `build-legacy.ps1` / legacy rollback
- 旧 PowerShell 安装自动迁移
- `msvc_list.json`
- `-config`、`-std`、`-type`、`-run`、`-env`、`-flags`、`-link_flags` 等旧单横线别名

请使用 `mqb --help` 展示的原生 CLI。旧拼写直接失败，不会进入兼容执行路径。

### 安装

1. 下载 `msvc-quick-build-v5.0.0-windows-x64.zip` 与 `.sha256`。
2. 校验 SHA-256。
3. 解压 ZIP。
4. 运行 `install.bat`。
5. 新开终端执行 `mqb --help`。

首行应为：

```text
MQB 5.0.0 - MSVC Quick Build (C++ refactor)
```

安装器默认安装到 `%USERPROFILE%\bin`，不修改 PowerShell profile，也不创建兼容命令。

卸载：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$HOME\bin\uninstall-mqb.ps1"
```

### 发布完整性

`Native Release` 要求同一 tagged commit 完成：

1. 固定历史 MQB seed 的 checksum / identity 验证；
2. seed → current Stage 0；
3. Stage 0 使用 MQB 构建并运行 67/67 Release tests；
4. Stage 0 → Stage 1；
5. clean Stage 1 → Stage 2 自举闭包；
6. Stage 1 打包；
7. exact ZIP SHA-256 / manifest / Stage 1 byte identity；
8. 从解压 ZIP 执行 install / reinstall / uninstall；
9. tag 与 `release/VERSION` 完全匹配后，publication job 发布同一 workflow run 已验证 artifact，不重建。

发布包中的 `mqb.exe` 使用静态 MSVC runtime，因此 MQB 本身不要求额外安装 Visual C++ Redistributable。

### 当前模块边界

External / prebuilt named-module providers 与 `import std;` 仍明确不支持并 fail closed，独立于 stable-v5 发布主线跟踪。

### 历史预发布

`v5.0.0-rc.1` 与 `v5.0.0-rc.2` 保留为历史 prerelease，不会重写。

## English

`v5.0.0` is the first stable release from MQB's native C++ mainline and the first stable release after the clean break from the former PowerShell implementation.

Stable v5 supports one executable (`mqb.exe`), one installed command (`mqb`), and one project configuration format (`mqb.json`).

### MQB-built end to end

MQB is its own development, test, and stable-release build system. The stable-v5 development/test/publication chain does not use CMake or CTest to generate or execute the MQB test graph.

For the first stable release, CI solves the bootstrap problem with the historical `v5.0.0-rc.2` MQB binary as a **pinned seed**. The historical release ZIP SHA-256 and executable identity are verified. The seed only builds current-source Stage 0 and is never packaged.

```text
pinned historical seed MQB (SHA-256 verified)
        ↓  MQB builds current 42-TU source set
Stage 0 (current source / Release test generation)
        ↓  Stage 0 builds and runs 67/67 Release tests with MQB
Stage 0 → Stage 1 (MQB builds MQB)
        ↓  delete cpp/.mqb
Stage 1 → Stage 2 (MQB builds MQB again)
```

Stage 0, Stage 1, and Stage 2 must all report `MQB 5.0.0`. The stable ZIP packages **Stage 1 only**, and the packaged `mqb.exe` must be byte-identical to the validated Stage 1 executable.

### Native 67-test gate

`tests/native/run_native_tests.ps1` is the authoritative test driver. It uses the production source manifest from `cpp/mqb.json`, requires exactly 67 `*_tests.cpp` entries, builds every test executable with MQB, passes the current MQB to CLI E2E tests, and directly executes all 67 tests.

### Breaking changes from the PowerShell line

Stable v5 does not ship or support `build.ps1`, a `build` compatibility command, legacy rollback, automatic migration of old PowerShell installations, `msvc_list.json`, or PowerShell-era single-dash aliases.

### Install

Download `msvc-quick-build-v5.0.0-windows-x64.zip` and its `.sha256`, verify the checksum, extract the ZIP, run `install.bat`, then open a new terminal and run `mqb --help`.

Expected first line:

```text
MQB 5.0.0 - MSVC Quick Build (C++ refactor)
```

The default install root is `%USERPROFILE%\bin`. The installer does not modify PowerShell profiles or create compatibility commands.

### Package integrity

The tagged `Native Release` run verifies the pinned seed, builds current Stage 0 with MQB, builds/runs 67 Release tests with Stage 0, proves Stage 0 → Stage 1 → clean Stage 2 closure, packages Stage 1, verifies the exact ZIP/checksum/manifest/Stage 1 byte identity, runs the packaged installer lifecycle, and publishes that already-validated artifact without rebuilding.

### Unsupported module boundary

External/prebuilt named-module providers and `import std;` remain intentionally unsupported and fail closed. They are tracked independently from stable v5.

### Historical prereleases

`v5.0.0-rc.1` and `v5.0.0-rc.2` remain historical prereleases and are not rewritten.
